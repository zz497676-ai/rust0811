# 01 — 概览:目标、动机与边界

## 1.1 一句话定义

cube3 是一个**三维电子表格**:在传统的「行 × 列」二维网格之外,增加「层(Layer)」作为
第三根轴。单元格的完整地址是 `(layer, row, col)`,公式可以沿任意一根轴引用、聚合与填充。

交付两件东西:

- `cube3-core` —— 数据模型 + 公式引擎,纯计算,零 IO,可被任何前端复用
- `cube3` —— 终端交互界面(TUI),把三维模型变成能上手编辑的东西

外加 `cube3-io` 负责存档格式与 `.xlsx` 双向互通。

---

## 1.2 为什么需要第三根轴

电子表格用户每天都在**用二维工具模拟三维数据**,而且模拟得很痛苦。三种典型场景:

**场景 A:同构报表的时间序列。**
12 个月,每个月一张结构完全相同的损益表。用户要么把 12 张表并排铺在一个 sheet 里
(行列错位、公式复制噩梦),要么开 12 个 sheet(汇总时被迫写 `Sheet1:Sheet12!B2`,
而且改一次结构要手工同步 12 遍)。

**场景 B:多情景假设分析。**
乐观 / 中性 / 悲观三套假设,跑同一个财务模型。Excel 的 Scenario Manager 弱到没人用,
实践中就是复制三份 sheet,然后祈祷它们不会失去同步。

**场景 C:多主体合并。**
5 个子公司,同一张科目表,要看合并数与单体数。同样是复制 N 份 + 手工汇总。

这三个场景的共同结构是:**一堆结构同构的二维表,沿某根语义轴排列,需要在这根轴上做
引用与聚合**。Excel 的 sheet 恰好长得像这根轴,但它不是轴 —— sheet 之间没有序、没有
相对引用、没有跨 sheet 填充,3D 引用只在少数函数里可用。

cube3 的赌注是:**把这根轴做成真的轴,上面三个场景就都变成一行公式的事。**

## 1.3 三维模型的四条核心能力

### (1) 三轴对称的引用

`$` 可以独立作用于层、列、行三根轴,填充时三根轴对称地变化:

| 操作 | 变化的轴 |
|---|---|
| 向右填充 | 列 |
| 向下填充 | 行 |
| **跨层填充** | **层** |

### (2) 相对层引用 `L[-1]!`

这是相对 Excel 的实质增量。`L[-1]!B2` 表示「前一层的 B2」,它在每一层求值时解析到不同的
目标层 —— 于是「环比增长」「期初 = 上期期末」「滚动累计」这类**沿深度轴递推**的计算,
可以写成一条能跨层复制的公式:

```
2024-02 层的 B10:  =L[-1]!B10 + B5 - B6      期初余额 = 上月期末 + 本月收 - 本月支
2024-03 层的 B10:  (同一条公式,跨层填充即可)
```

Excel 里这件事必须逐 sheet 手写 `=Jan!B10 + B5 - B6`、`=Feb!B10 + B5 - B6`……,插入一个
月份就全线断裂。

### (3) 长方体区域(Cuboid)

区域从矩形升级为长方体:`Q1:Q4!B2:B10` 是「4 个层 × 9 行 × 1 列」共 36 个单元格。
所有接受区域参数的函数(`SUM` / `AVERAGE` / `COUNT` / `MAX` …)天然接受长方体,按
层 → 行 → 列 的顺序展平。

### (4) 深度视图

交互层面的核心创新:光标在任意单元格上按 `d`,侧栏纵向列出该 `(row, col)` 在所有层的值,
并可原地编辑。这是二维界面里根本无法呈现的信息切面 —— 相当于免费得到了一个「跨表对比」
视图,而且始终与数据同步。

## 1.5 非目标(MVP 明确不做)

写清楚不做什么,和写清楚做什么同样重要。以下内容**不要实现**,即使看起来只差一点:

- **图表、透视表** —— 与三维模型的核心价值无关,体量巨大
- **条件格式** —— 需要完整的样式规则引擎
- **宏 / VBA / 脚本** —— 需要第二套语言运行时
- **协同编辑 / 多人在线** —— 需要 CRDT 与网络层
- **合并单元格** —— 与三维地址模型冲突严重,需要单独设计
- **富文本样式** —— MVP 的 `Style` 只保留数字格式、水平对齐与粗体(见 [02](02-data-model.md#26-样式));
  不做字体、颜色、边框
- **数组公式 / 动态数组溢出** —— Excel 的溢出语义复杂,MVP 里函数只返回标量
- **迭代计算(允许循环引用并迭代收敛)** —— MVP 直接把循环引用判为错误
- **撤销/重做的无限历史** —— MVP 只做固定深度 100 步的操作栈

这些都是**合理的后续方向**,但不属于 MVP。执行者不应主动实现它们;若确有必要,先提出来。

## 1.6 与 Excel 的关系

**语义上向 Excel 看齐,能力上是它的超集。** 具体地:

- 运算符、类型强转、错误值语义,一律与 Excel 一致(spec 未写到的部分见
  [README 须知第 3 条](README.md#给执行者的须知))
- 函数名与参数顺序与 Excel 同名函数一致,差异必须在
  [03 的函数表](03-formula-language.md#35-内置函数表)里逐条列出
- 层向函数(`LAYERSUM` / `PREV` / `DELTA` …)与相对层引用是 cube3 独有的扩展
- 导出 xlsx 时,cube3 独有的表达能力会**尽力翻译、无法翻译则降级为静态值并保留原公式到
  批注**,规则见 [05](05-persistence.md#54-公式导出翻译规则)

一句话:**从 Excel 导入的东西不丢,导出到 Excel 的东西能打开。**

## 1.7 术语表

统一术语,代码标识符与文档叙述都用这一套:

| 中文 | 英文标识符 | 含义 |
|---|---|---|
| 工作簿 | `Workbook` | 顶层文档,持有全部层 |
| 层 | `Layer` | 第三根轴上的一个切片,即一张二维网格 |
| 层序号 | `LayerIndex` | 层在工作簿中的位置,从 1 开始(面向用户) |
| 层 ID | `LayerId` | 层的稳定标识,与位置无关,重排/改名不变 |
| 单元格 | `Cell` | `(layer, row, col)` 上的一个格子 |
| 地址 | `Addr` | 一个具体单元格的三维坐标(已解析、绝对) |
| 引用 | `Ref` | 公式里写的引用,可能含相对/绝对标记,需在某个上下文中解析成 `Addr` |
| 长方体 | `Cuboid` | 三维区域,层区间 × 行区间 × 列区间 |
| 深度视图 | Depth View | TUI 中沿层轴纵向展示同一 `(row, col)` 的侧栏 |
| 值 | `Value` | 单元格的计算结果 |
| 输入 | `CellInput` | 用户键入的内容(字面量或公式) |
